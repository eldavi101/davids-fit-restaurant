# API_SPEC.md

Base URL: `https://<host>/api/v1`
Auth: `X-API-Key: <key>` on every endpoint except `/health`.
All timestamps in responses are **ISO-8601 UTC** (`2026-08-07T14:32:10Z`); the
client renders them in America/New_York.
Errors use RFC-7807-style bodies: `{"error": {"code": "...", "message": "...", "detail": {...}}}`.

Interactive schema: `GET /docs` (OpenAPI 3.1 generated by FastAPI).

## Stocks

### `GET /stocks/{ticker}`
Instrument profile + latest quote + eligibility and its reason.

### `GET /stocks/{ticker}/analysis`
Full explainability payload: every component score with its sub-components and
contributions, `rules_passed`, `rules_failed`, indicator values, fundamentals,
risk block, probability block (with sample size and CI), stop/targets, and the
`buy_reasons` that *would* be recorded.

### `GET /stocks/{ticker}/bars`
Query: `timeframe` (`1d` default), `limit` (≤ 1500), `from`, `to`.
```json
{"ticker":"NVDA","timeframe":"1d","bars":[
  {"ts_utc":"2026-08-06T20:00:00Z","o":181.2,"h":185.0,"l":180.9,"c":184.32,"v":41230000}
],
 "overlays":{"ema20":[...],"ema50":[...],"sma200":[...],
             "rsi14":[...],"macd":[...],"macd_signal":[...],"macd_hist":[...],
             "obv":[...],"rs_line":[...]},
 "markers":[{"type":"BUY","ts_utc":"...","price":184.32,"alert_uid":"..."},
            {"type":"SELL","ts_utc":"...","price":198.70,"alert_uid":"..."}],
 "levels":{"stop":179.80,"target1":191.10,"target2":197.88}}
```

### `GET /stocks/{ticker}/signals`
Signal history for this ticker (all past BUY/SELL alerts).

## Alerts

| endpoint | returns |
|---|---|
| `GET /alerts` | all alerts, newest first |
| `GET /alerts/buy` | BUY alerts only |
| `GET /alerts/sell` | SELL alerts only |
| `GET /alerts/active` | alerts in an open status |
| `GET /alerts/closed` | closed trades |
| `GET /alerts/{id}` | one alert by numeric id or `alert_uid` |
| `GET /alerts/{id}/timeline` | the permanent event timeline |

Common query params: `status`, `ticker`, `sector`, `strategy_version`,

## Positions & history

### `GET /positions`
Paper positions with shares, cost basis, current price, unrealized/realized P&L,
stop, targets, risk amount and `% of equity`, plus a portfolio summary block
(equity, cash, open risk, sector exposure, correlation clusters).

### `GET /history`
Closed trades with filters `from` `to` `ticker` `sector` `strategy_version`
`outcome` (`winner|loser|stopped|target|all`) `min_return` `max_return`.

## Backtesting

### `POST /backtests`
```json
{"mode":"WALK_FORWARD",            // BACKTEST | WALK_FORWARD | OOS
 "start_date":"2018-01-01","end_date":"2025-12-31",
 "universe":["NVDA","AMD","..."],  // optional; defaults to the eligible universe
 "strategy_version":"momentum_breakout_v1.0.0",
 "parameter_overrides":{"min_opportunity_score":82,"stop_atr_mult":2.0},
 "initial_equity":100000,
 "costs":{"slippage_bps":5,"spread_bps":4,"commission_per_trade":0.0},
 "walk_forward":{"train_years":4,"test_years":1,"step_years":1,"anchored":false}}
```
→ `202 Accepted` with `{"run_uid":"…","status":"QUEUED"}`.

### `GET /backtests` · `GET /backtests/{id}` · `GET /backtests/{id}/trades`
Run status, aggregate metrics, per-fold train/validation/test metrics, equity curve,
monthly returns, and the trade blotter.

## Settings

### `GET /settings` / `PUT /settings`
Every `StrategyConfig` and portfolio field, grouped by category
(`universe`, `scoring`, `buy_gate`, `sell_engine`, `risk`, `portfolio`,
`scheduler`, `data`), each with `value`, `default`, `type`, `min`, `max`,
`description`. `PUT` accepts a partial object, validates, persists to `settings`,
and returns the merged effective configuration.

Changing scoring weights or gate thresholds **creates a new strategy version** when
`create_version: true` is passed; otherwise the change is rejected for any field
that affects historical comparability.

## System

| endpoint | purpose |
|---|---|
| `GET /health` | liveness, no auth |
| `GET /system/status` | DB reachable, provider health, last scan/monitor times, queue depth, error counts, degraded flags |
| `POST /system/scan` | trigger an immediate scan (admin) |
| `POST /system/monitor` | trigger an immediate monitor pass (admin) |
| `GET /audit` | audit log, filterable by ticker/decision/stage/date |

## Sync

### `GET /sync?since=<iso8601>`
One round-trip for the Android background worker: returns changed alerts, changed
positions, the latest scanner snapshot, market status, regime and analytics, plus
`server_time_utc` and `next_since`. This is what WorkManager calls.

## Rate limits & pagination

Default 120 req/min per API key. All list endpoints are `limit`/`offset` paginated
and return `total`. Responses are gzip-compressed.
