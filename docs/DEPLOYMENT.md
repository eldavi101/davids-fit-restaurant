# DEPLOYMENT.md

How to take this repository from "an APK that shows nothing" to "an APK showing real
signals from real market data".

The APK cannot do this alone, by design: it holds no market-data credential and runs no
scanner. It is a view over a backend you control. So the work below is (1) stand the
backend up, (2) give it a data vendor, (3) point the phone at it.

---

## 0. What you have to supply

Four things, none of which can be committed to this repository or embedded in the APK:

| # | What | Why it can only come from you |
|---|---|---|
| 1 | **A market-data provider account and API key** — Polygon, Finnhub, FMP, Twelve Data or Alpha Vantage | It is a paid (or rate-limited free) account in your name. The system never scrapes, and never invents prices. |
| 2 | **A machine to run the backend** — your laptop, a VPS, Fly.io, Railway, Render… | The scanner and the post-signal monitor must keep running while the phone is asleep. |
| 3 | **A hostname with HTTPS**, if the phone will use it outside your own Wi-Fi | The release build permits no cleartext traffic. On your own LAN the debug APK is enough. |
| 4 | **Two values typed into the app**: backend URL and API key | The API key is generated by the setup script; you copy it into Settings. |

Everything else — schema, universe, first scan, scheduling — is automated below.

**Never paste a vendor key into a chat, an issue, a commit, or the app.** It belongs in
`backend/.env` on the server and nowhere else. `.env` is git-ignored.

---

## 1. Choosing a provider

The strategy needs, per symbol, ~400 daily bars of history. A full universe refresh costs
one history request per symbol that survives the exchange/security-type filters; a scan
costs one more per eligible symbol. That makes the *request rate* the deciding factor, not
the price of the plan.

| Vendor | Free tier | Practical verdict | Fundamentals? | Delisted history? |
|---|---|---|---|---|
| **Polygon.io** | 5 req/min | Free tier is unusable for a universe scan; the paid Stocks plan is unmetered and is the best fit | no | yes — the only one that supports survivorship-bias-free backtests |
| **Finnhub** | 60 req/min | Workable free tier; good fundamentals coverage | yes | no |
| **FMP** | daily cap | Fine on a paid Starter plan | yes | no |
| **Twelve Data** | 8 req/min | Too slow for a broad universe; fine with `UNIVERSE_MAX_SYMBOLS` set low | no | no |
| **Alpha Vantage** | 5 req/min, 25 req/day | Not viable as a primary source; usable as a fallback | no | no |

Set `MARKET_DATA_RATE_LIMIT_PER_MINUTE` to what your plan actually grants. The client
paces itself to that number, because a 429 costs a request *and* produces no data — the
scanner then correctly refuses to signal, so an unpaced deployment simply never alerts.

If your plan is slow, cap the universe rather than letting a refresh run for hours:

```
UNIVERSE_MAX_SYMBOLS=1500
```

`synthetic` remains available and needs no key. It generates deterministic prices, labels
them `SYNTHETIC` everywhere they surface, and must never be traded on. It exists so the
app can be demonstrated end to end without a vendor account.

## 2. The fast path (Docker, one command)

On the machine that will run the backend:

```bash
git clone <this repo> && cd <repo>/backend
./scripts/setup.sh
```

The script:

1. asks which provider you use and reads the key **without echoing it**;
2. generates a random backend API key and a random Postgres password;
3. writes `backend/.env` with mode `600` (git-ignored);
4. builds and starts Postgres + the API;
5. runs `python -m app.cli bootstrap` — schema, universe, first scan, first monitor pass;
6. prints the backend URL and API key to type into the app.

Nothing else is needed for a LAN setup. Skip to §5.

---

## 3. The manual path

```bash
cd backend
cp .env.example .env && chmod 600 .env
```

Edit `.env`:

```
APP_ENV=production
API_KEYS=<openssl rand -hex 32>          # what the Android app sends as X-API-Key
POSTGRES_PASSWORD=<openssl rand -hex 32>
MARKET_DATA_PROVIDER=polygon             # or finnhub | fmp | twelvedata | alphavantage
POLYGON_API_KEY=<your key>
MARKET_DATA_RATE_LIMIT_PER_MINUTE=100    # your plan's real limit
ENABLE_SCHEDULER=true
```

Then:

```bash
docker compose up -d --build db api      # Postgres + API
docker compose run --rm bootstrap        # schema + universe + first scan
```

Without Docker, any Python 3.11+ host works:

```bash
python -m venv .venv && .venv/bin/pip install -e ".[postgres]"
export DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/equity_signal
.venv/bin/python -m app.cli bootstrap
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### The database

`app.cli init-db` (also the first step of `bootstrap`) creates all 17 tables and is
idempotent — safe to re-run on every deploy. There is no migration tool wired in yet, so
a future schema change to an existing production database will need either a hand-written
`ALTER TABLE` or Alembic added at that point. Fresh installs are fully covered.

Back up the `pgdata` volume. Alert history is append-only and is never recreated from the
vendor: once a BUY alert exists, its entry snapshot is the only record of what the system
saw at that moment.

SQLite works for a single-user deployment and needs no extra service, but Postgres is what
the concurrent scanner + API + monitor pattern is designed for.

## 4. HTTPS (needed for anything beyond your own Wi-Fi)

The Android release build refuses cleartext, so a phone on mobile data can only talk to an
HTTPS endpoint. The compose stack includes Caddy, which obtains and renews a Let's Encrypt
certificate automatically.

1. Point a DNS A record at the server.
2. Open ports 80 and 443.
3. In `.env`:
   ```
   PUBLIC_DOMAIN=signals.example.com
   API_BIND_HOST=127.0.0.1        # stop exposing plaintext 8000 to the network
   CORS_ORIGINS=https://signals.example.com
   ```
4. `docker compose --profile tls up -d`

The app's backend URL is then `https://signals.example.com/api/v1/`.

A backend published under a subpath (`https://example.com/equity/api/v1/`) also works —
the client preserves the prefix.

## 5. Connecting the app

1. Download `equity-signal-debug-apk` from the latest green run of
   `.github/workflows/android.yml`, unzip, install `app-debug.apk`.
2. Open the app → **Settings → Backend**.
3. **Backend URL**:
   - same Wi-Fi as the backend: `http://192.168.x.x:8000/api/v1/`
   - Android emulator on the same machine: `http://10.0.2.2:8000/api/v1/`
   - public deployment: `https://your-domain/api/v1/`
4. **API key**: the `API_KEYS` value from `.env`.
5. Save. The screen immediately loads strategy settings from the backend, so a wrong URL
   or key shows up as an error right there rather than as a silently empty app.

Cleartext over the LAN works because the **debug** variant ships a permissive network
security config (`app/src/debug/res/xml/network_security_config.xml`). The release variant
does not: it is HTTPS-only.

## 6. Verifying it actually works

```bash
docker compose exec api python -m app.cli check
```

It reports the database, the provider (including whether the key is accepted), the
scheduler state, and whether `API_KEYS` still holds a placeholder. Then:

```bash
curl -H "X-API-Key: $KEY" http://localhost:8000/api/v1/system/status
```

What "working" looks like:

- `instruments` and `eligible_instruments` are non-zero — the universe was built;
- `last_scan_utc` is recent and `last_regime` is set — the scanner ran;
- `active_provider` is your vendor, not `synthetic`;
- in the app: Home shows market status, Scanner shows a ranked list.

**An empty Alert Center is not a fault.** The BUY gate requires 13 independent conditions
to agree, and blocks entirely in a BEAR regime. Days with no alert are the normal case —
that is the point of the gate. Use the Scanner tab to see what is being evaluated and how
close it came, and `GET /audit` to see exactly which rule blocked a given ticker.

## 7. Operating it

| Task | Command |
|---|---|
| Follow the scanner | `docker compose logs -f api` |
| Force a scan now | `docker compose exec api python -m app.cli scan` |
| Scan a few tickers | `… app.cli scan --tickers NVDA,AMD,AVGO` |
| Re-check open alerts | `docker compose exec api python -m app.cli monitor` |
| Rebuild the universe | `docker compose exec api python -m app.cli universe` |
| Re-run the config check | `docker compose exec api python -m app.cli check` |

The scheduler scans every `SCAN_INTERVAL_MINUTES` and monitors every
`MONITOR_INTERVAL_MINUTES`, but only while the market is open, pre-market or shortly after
the close — scoring stale intraday data adds noise, not information. The universe rebuilds
daily at `UNIVERSE_REFRESH_HOUR_ET`.

The app's `SyncWorker` polls the backend on its own cadence (Settings → Sync interval) and
raises a **local** notification for each new alert. There is no external notification
channel of any kind — no email, no messaging service, no webhook. Alerts live in the app.

## 8. Security notes

- Vendor keys never leave the backend. The app holds only your own `X-API-Key`.
- `.env` is git-ignored and written `600`; `.gitignore` also excludes keystores.
- The API is fail-closed: an empty `API_KEYS` rejects every request rather than allowing
  them.
- Postgres is published on loopback only.
- Rotating the app key means editing `API_KEYS`, restarting the API, and updating
  Settings on the phone. `API_KEYS` accepts a comma-separated list, so you can add the new
  key, migrate, then drop the old one.
- `PAPER_TRADING=true` is the default and the only implemented mode. Nothing here places
  a broker order.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| App shows "Could not refresh" | wrong URL, wrong key, or backend unreachable | `app.cli check`; confirm the phone is on the same network |
| Cleartext connection blocked | release build, or a debug build talking to a non-LAN host | use HTTPS (§4) |
| `provider rejected the API key` | wrong key, or provider not enabled for that endpoint | re-check the vendor dashboard |
| Universe refresh takes forever | plan is rate-limited | set `MARKET_DATA_RATE_LIMIT_PER_MINUTE` and `UNIVERSE_MAX_SYMBOLS` |
| `eligible_instruments` is 0 | filters too strict for the data returned, or no market cap from the vendor | `GET /audit`, then relax `min_market_cap` / `min_avg_dollar_volume` in Settings |
| Scan aborts with "SPY unavailable" | vendor cannot serve the benchmark | check entitlements; the regime engine needs SPY |
| Prices marked `SYNTHETIC` | `MARKET_DATA_PROVIDER=synthetic` | set a real vendor and restart |
| No alerts for days | normal — the gate is strict | check Scanner and `GET /audit` for the blocking rules |
